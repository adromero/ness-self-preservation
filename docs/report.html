Verdict — the four NESS signatures

YES

Signature 1: Steady state under throughput

21 viable (r>0) operating points; best steady state 95.8% ± 0.1 at d=0.002, r=8 — a plateau 1.1 pts below the clean ceiling (96.9%).

YES

Signature 2: Collapse on starvation

At the operating decay rate d=0.02, cutting repair (r=0) collapses the steady state to 13.4% and prolonged starvation of the running network drives it to 10.2% — the 15% death line, essentially chance (10%). Metabolism is load-bearing: without repair, throughput-driven decay is lethal. (Only near-zero decay, d≤0.005, survives without repair.)

SHARP

Signature 3: Phase transition (sharp boundary)

Steepest drop 2.22 accuracy per decade of decay (a step-like transition). Primary death edge (r=0: dies at d≈0.0114; r=1: dies at d≈0.0143; r=2: dies at d≈0.0151; r=4: dies at d≈0.0236; r=8: dies at d≈0.0266) moves to faster decay as repair rises — more metabolism buys tolerance. A secondary effect: at very high decay (d≈0.16) columns r=[1, 2, 4, 8] partly revive — repair re-learns from near-random weights each tick, so the phase structure is richer than a single boundary.

YES

Signature 4: Irrecoverability / hysteresis

Strong hysteresis. Turning repair back on after starvation does not restore the network: post-recovery accuracy sits at chance for every starvation tested (point of no return ≤25 ticks). Even a lightly-starved state that is still 53% accurate cannot be rebuilt — repair *maintains* a steady state but cannot *climb back* to it. Caveat: the operating point (d=0.02, r=4, steady state ≈62%) sits near the transition, so its basin is small; a more deeply-alive point may be more forgiving — worth a targeted follow-up.

Methods & integrity

Design (unchanged from the submitted script): pretrained MLP on MNIST; each tick applies multiplicative Gaussian weight noise scaled by per-layer std plus a small fraction of weight zeroing (decay), optionally followed by r SGD steps on fresh data (repair). Steady-state accuracy = mean of the last 25% of a 1500-tick run.
Fixes applied (bugs, not design): (1) the probe operating point for starvation/recovery is now auto-selected from the sweep (the script's own “adjusted below based on sweep if needed” comment was never implemented, so signatures 2&4 could have started from a dead state); here it resolved to d=0.02, r=4. (2) The whole experiment is repeated with fresh seeds for 4 replicates so every number above carries an error bar rather than a single noisy draw. Physics, model, grid, and thresholds are exactly as submitted. Limitation: the full 7×6 grid at 1500 ticks costs ~2.7 h per replicate (the r=8/16 columns dominate), so only 4 replicates fit in the budget — error bars (std of 4) are indicative, not tight; a larger n would need a longer run or a trimmed grid.
Grid note: the r=16 repair column was trimmed for this run (it cost ~1h/replicate); repair spans 0..8, so more replicates fit and the error bars tighten. Data: per-tick log results/log.csv (with replicate id), aggregates results/sweep_agg.csv and results/recovery_agg.csv.
